# LLM 决策管线接入设计（TBD-34 提案载体）

> 文档类别：长期维护，登记于 [docs/00-rules-registry.md](00-rules-registry.md)。
> 位置：LLM 是**判读层之上的解读者与假设生成器**，运行于研究进程（G-01、T-13：永不持有 TRADE 密钥）；其输出是判定与候选，不是指令——通往执行的唯一路径是既有闸门链（G-05 转换点、T-12 三级阶梯、A-01 人工确认），**结构上不存在 LLM 直达下单的通路**。
> 判读事实的上游结构见 [footprint-design.md](footprint-design.md) 第 6.4 节（analysis_run 台账与 book_feature 事件流）。

## 1. 输入构造（决策请求包）

一次请求 = 一个内容寻址的 JSON 包（`input_hash` = 包体 SHA-256），装配器版本化，装配严格遵守 point-in-time（D-04）：**只装 `available_time <= decision_time` 的数据**，包内自带该断言字段。金额域一律字符串（T-08 在边界处保原文）。七段构造：

| 段 | 内容 | 来源 |
|---|---|---|
| 标的与规则 | venue、symbol、tickSize、sizeStep、会话界、当前基准 | instrument_map 与品种规则 |
| 尺度定位 | 桶档或周期、时间窗起讫、价带（如有） | 请求方声明（尺度链上的位置，ui-design 4.5） |
| 市场事实序列 | OHLC、Delta、CVD、五带（Spread、OFI、盘口不平衡、Trade Delta、Depth bp）、足迹汇总（POC、VA、合计） | 瓦片与足迹聚合，**定长降采样**（每序列点数上限入配置并随包声明，禁止变长喂食） |
| 判读事实 | 窗内 analysis_run 全量四判定（逐条件子分、置信度、met）、book_feature 事件、报警状态 | 判读台账（全量，含不成立者——负样本一并可见） |
| 数据质量 | 空档与延载占比、partial 旗标、完整性等级、数据源（archive 或 live，live 含侧别推断声明） | 瓦片列态与覆盖表 |
| 溯源 | `code_version`、`config_hash`、装配时刻、PIT 断言 | 装配器（D-09 双钥） |
| 提问 | 枚举化任务类型加对应输出 schema_id | 请求方 |

三条纪律：**不喂自由文本行情**（新闻等文本源将来按多源纪律独立登记，不混入本包）；**不喂密钥不喂账户身份**；包体本身追加式归档——LLM 看过什么，永远可复查。

## 2. 输出构造（结构化裁断）

输出必须命中版本化 JSON schema（`schema_id` 随提问段声明），**校验失败即按数据错误丢弃并记录，不做宽容解析**（C-03 精神）。逐问回答的统一形制：

```json
{
  "claim": "<枚举值或类型化值>",
  "confidence": "0 至 1",
  "evidence": ["输入包内字段路径引用"],
  "reasoning_digest": "<限长摘要，入库不入界面>",
  "abstain": false
}
```

初期四类提问与其 claim 域：

| 任务类型 | claim 形态 | 去向 |
|---|---|---|
| 状态判读 | 市场状态枚举（平衡、单边、真空后脆弱等，枚举表版本化） | 研究输入与监控标注（判读层形制呈现） |
| 事件复核 | 对某判定的同意与否加引证 | 与检测器判定并列入台账，二者分歧即标定素材（TBD-30） |
| 关注清单 | 价带与时段的有序列表 | OFL 标注层候选（判读层开关内） |
| 假设生成 | **候选因子表达式**（表达式文法版本化） | 直接进入既有候选管线：`candidate_id` 内容寻址、试验台账全量登记（G-07）、封存段一次消费（G-08）、多重检验全量计数 |

**输出永不含**：下单参数、数量、价格指令、对限额与运行模式的任何表述。假设生成类的表达式若含金额语义，仍须经 G-05 唯一转换点才能触碰下单参数——LLM 只是又一个候选来源，不享任何豁免。

## 3. 台账与评估

- `llm_run` 追加式台账：`input_hash`、模型标识、参数散列（温度与种子在内）、输出原文、`schema_id`、时延、token 计数、`code_version`。同 `input_hash` 可重放对比输出漂移（模型更替与退化检测）。
- 评估闭环：裁断与事后实现的市场事实联结计分，计入试验台账——LLM 的判读准确率是被度量的研究对象，不是被信任的前提。评分函数版本化。
- 界面呈现（如有）一律判读层形制：默认关、判定不是事实、零结论句。

## 4. 扩展预留

- **视觉输入**：热力图瓦片渲染 PNG 作为多模态输入（图像同样内容寻址入包）；文本先行，视觉后评估增益再启。
- **多模型**：`llm_run` 的模型标识域即天然支持并行多模型对照裁断（分歧本身是信号）。
- **在线频度**：初期离线批式（研究节奏）；若升实时辅助，请求节奏与成本预算入配置（G-06），且不改变「无下单通路」结构。

## 5. 环境适应策略架构（TBD-08 与 TBD-17 的提案素材，归属见第 8 节）

目标结构不是“LLM 看图后选一个策略”，而是事实、统计模型、LLM 与执行安全各自承担可验证职责：

```text
PIT 市场事实 ──> 环境状态估计 ──> 策略资格闸门 ──> 组合分配器 ──> 风险闸门 ──> 执行器
       │                │                 │               │
       └──> LLM 解读与假设 ──> 结构化候选/分歧台账 ────────┘
```

| 层 | 责任 | 禁止事项 |
|---|---|---|
| 事实层 | 统一时钟、PIT 特征、覆盖与质量状态、成本和可交易性 | 用插值掩盖缺口；用事后修订值污染决策时点 |
| 状态估计 | 输出带概率和不确定度的波动、趋势、流动性、拥挤、事件与跨所离散状态 | 直接给订单；把硬标签当永真市场状态 |
| 策略资格闸门 | 按数据、容量、库存、延迟、账户和市场状态决定策略是否 eligible | 用预期收益覆盖硬风险条件 |
| 组合分配器 | 在 eligible 策略间分配风险预算，计入相关性、换手与切换成本 | 瞬时全切；忽略策略间共同暴露 |
| 风险与执行 | 确定性限额、价格保护、库存、撤单、熔断与 kill switch | 接收自由文本；允许模型绕过规则 |
| LLM | 解释状态、复核规则、提出候选、识别遗漏和输出证据路径 | 下单、改限额、选择账户或持有交易密钥 |

环境状态至少包含六组：波动与跳跃、趋势与均值回复、点差与深度、OFI/成交主动性、跨所基差与资金成本、事件风险与数据质量。状态估计采用统计模型或小型监督模型为主；LLM 只能读取其版本化结果并指出矛盾，不能代替数值估计器。

策略注册表统一描述趋势、均值回复、跨所套利、做市、统计套利/中性、事件驱动等专家：`strategy_id/version`、所需来源、允许状态、禁止状态、容量、持仓周期、成本模型、风险暴露、warmup、最短驻留、冷却和退出条件。注册表缺一项即不得进入 eligible。

切换采用迟滞而非 winner-takes-all：进入阈值高于退出阈值，带最短驻留、冷却期、换手惩罚和 OOD abstain。旧策略先降风险，新策略经 shadow/canary 后升权；两者交接写入同一个 `allocation_snapshot`，风险预算总和在事务边界内守恒。

## 6. 台账与自我完善闭环

追加五类事实，所有学习只消费这些事实的已封存版本：

| 台账 | 最小内容 |
|---|---|
| `environment_snapshot` | 决策时点、状态概率、不确定度、输入散列、质量闸门与模型版本 |
| `strategy_eligibility` | 每策略逐条件 eligible/blocked、观测值、阈值和原因码 |
| `allocation_snapshot` | 旧权重、新权重、风险预算、切换成本、触发来源和人工覆盖 |
| `strategy_run` | 信号、意图、风控裁剪、订单/成交关联、成本与事后归因 |
| `llm_run` | 输入散列、结构化输出、证据路径、模型/参数版本、延迟和 token 成本 |

自我完善流程为离线候选生成、purged walk-forward、成本与容量压力、shadow、canary、有限升权、漂移监控、自动降级。任何阶段失败都回到 blocked，不在线改写生产模型。LLM 发现的遗漏进入候选或数据质量工单，不直接改变资格规则。

## 7. 策略与切换的可视化

命令条右侧徽章组只保留一行决策摘要（术语按四区壳，形制受设计语言约束；作为交互入口与命令条静态占位裁定的关系待 TBD-17 定稿）：`环境状态 · 主策略/权重 · 风险利用率 · 数据新鲜度`。它是只读入口，点击进入研究页；不得在所有面板重复。颜色只编码已定义语义，并始终辅以文字、数值或纹理。

研究页采用三个同步视图：

1. **状态带**：横向时间带显示环境状态概率与 OOD/缺口纹理；颜色浓度表示概率，但必须固定色标，不能随当前窗口重新归一。
2. **策略泳道**：每策略一行，状态只取 `blocked → shadow → eligible → active → cooling`；形制和文字优先，颜色为辅。权重用细条长度，不用面积气泡。
3. **切换因果链**：选中一次切换后展示状态变化、资格条件、预期收益、成本、风险裁剪和最终权重；LLM 解释与数值证据并列，二者有分歧时显式标注。

策略切换控件只允许操作既有安全状态：观察、shadow、申请启用、申请降权/停用。实盘升权必须二次确认并走既有执行闸门；界面不存在“AI 自动下单”开关。动画只用于一次性表达权重交接，尊重 reduced-motion，不用循环脉冲暗示系统仍健康。
