## 2. 每日合并任务连续两日只留开始记录

`guvolu-trade-compaction`（09-21 登记于 03:53）在 09-22、09-23 均以退出码 1 结束，日志只有开始行。两个原因叠加：

| 原因 | 事实 |
|---|---|
| 与每日补漏相撞 | `guvolu-materializer-catchup` 03:16 起跑，此前 2 分钟结束；行情管线切到 `ForwardMinimal` 后 L2 派生物化只在这一步补做整日，09-23 实测 50 分钟，期间持主写锁；03:53 的合并等锁 120 秒即超时 |
| Windows PowerShell 的终止错误 | 脚本以 `Stop` 偏好运行，`2>&1` 收到子进程标准错误（写锁超时的回溯）即作为终止错误退出，市场行与结束行都没写 |

修复（提交 `f8c028f`）：任务改到 04:53；子进程调用期间偏好改为 `Continue`；写锁超时后每市场重试三次、每次间隔 60 秒。09-23 14:42 在轮次空窗手动运行一次：七个市场全部合并，BTC 活动实时头 863 降至 105、ETH 791 降至 91。

## 3. 两个 vintage 的每日预检自 09-18 起报 `would_burn`

BTC 预检任务自 09-18 起每日退出码 2：`verify_frozen_forward` 报「冻结前向预测制品散列不匹配」，阻断项指向决策时刻 2026-09-17T13:00Z。ETH 运行根没有预检任务，手动复核发现同类问题（2026-09-18T21:00Z）。

### 3.1 根因：两轮交错时预测先改写制品再被登记拒绝

| 时刻（UTC） | 进程 | 动作 |
|---|---|---|
| 09-17 12:12 | 上一轮（包装脚本 13:07 被任务时限终止，Python 成为孤儿继续运行） | 慢轮次进入过期重试 |
| 13:12 | 本轮 | 刷新快照、预测 13:00Z 决策柱 |
| 13:29:47 | 本轮预测进程 | 写制品（输入世代 `1ef0f258`、收据 `70dbdeb9`）并登记，登记散列 `e8496014` |
| 13:47:50 | 孤儿预测进程 | 以更新一代活动头（多两个五分钟段）再生成同一决策柱：先原子写入同名制品（散列 `55da12e3`），再向登记表登记，被「该决策时间的冻结前向预测不可改写」拒绝 |
| 14:07 | 孤儿 | 记录失败退出；制品已与登记不符 |

冻结运行根代码 `run_frozen_forward_prediction` 先 `atomic_write_text` 再 `register_frozen_forward_prediction`，登记表的不可改写约束保护了登记行，没有保护制品文件；单一编排进程下不会触发。ETH 09-18 20:30Z 与 21:30Z 两轮同样交错，形态一致。孤儿轮次已由 09-21 的包装脚本整树终止消除，本文只处理遗留损坏与再加一道编排侧防线。

### 3.2 修复：按登记身份重建制品字节

两个被改写的制品与登记行只在五个字段上不同：`input_head_generation`、`input_receipt`、`input_receipt_sha256`、`trade_input_qualification` 与 `panel` 内的世代与输入集合；`panel_sha256` 与全部策略输出相同（多出的两段只含决策柱之后的成交）。原始收据文件按内容寻址保留在运行根 `data/research/input-receipts/`，其 `head_generation` 等于登记世代，行数与资格计数直接取自收据。以冻结代码同一 `canonical_json` 序列化重建后，字节散列与登记散列完全一致：

| 运行根 | 决策时刻 | 登记散列 | 改写后散列 | 重建散列 |
|---|---|---|---|---|
| BTC `356b45e` | 2026-09-17T13:00Z | `e8496014408f` | `55da12e3f8e2` | `e8496014408f` |
| ETH `a42aac6` | 2026-09-18T21:00Z | `19cfa4bdd47c` | `998db9513a8e` | `19cfa4bdd47c` |

## 5. 教训

- 不可改写约束要同时覆盖登记行与制品文件：先写文件再登记的顺序在并发下会留下与登记不符的制品。冻结代码不可改，编排侧用运行根锁补齐。
- 只读复核要覆盖每个冻结运行根：ETH 的损坏存在五天无人知晓，因为预检只登记了 BTC。
- 计划任务的时刻要按邻近任务的实测时长排，不按其历史时长；配置切换（`ForwardMinimal`）会改变别的任务的时长。
- Windows PowerShell 脚本里所有子进程调用都要在 `Continue` 偏好下执行，`Stop` 偏好会把标准错误变成终止错误。
