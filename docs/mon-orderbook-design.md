# MON 盘口结构与指标改造设计

> [盘口判读设计](footprint-design.md)。
> 状态：已迁移到活动 L2 Parquet，并优先读取同 head 的
> `book_state_checkpoint`；展示新鲜度仍受封段与 L2 物化延迟约束。事件级动画须

## 1. 目标与边界

MON 的盘口回答三个扫读问题：最优买卖报价是否可交易、带内流动性在哪一侧、按固定金额进入或退出的成本是否可接受。它不是逐档研究工作台；完整档表、时间追踪和判读留在 OFL。

现有实现的价格列、数量列与中缝同列对齐，且最优卖价与最优买价分别靠近中缝。保留这一价格邻近性，不保留「两侧各按最大档缩放、全部条形向右生长」的视觉编码。后者不能比较买卖深度，也不能表达距中间价的结构。

本设计不从快照推断委托级撤单、队列位置、成交先后或挂单欺诈。档级净撤减与成交消耗的边界仍以 [footprint-design.md](footprint-design.md) 第 6 节为准。

## 2. 数据等级与呈现降级

| 等级 | 数据基础 | MON 可呈现 | 不可呈现 |
|---|---|---|---|
| 当前阶段 | 活动 L2 的已封口末态；优先 checkpoint、必要时确定性重放 | 最优买卖报价、带内深度、盘口不平衡、微价格、来源与 head 代际 | 未封口实时动画、档级变化归因、持续时间 |
| 下一阶段 | 增量 state/tile 与逐笔成交 | 250ms 批次变化、窗口成交流、持续性统计 | 委托级撤单与队列位置 |
| 研究阶段 | 录制的 WS 快照序列与逐笔成交 | OFL 档带追踪、快照近似的净增挂/净撤减/成交消耗 | 真 L2 回放 |

每个响应必须给出来源、事件时刻、可用时刻、活动 head 和覆盖范围。当前 v2 的
`as_of` 是重放末帧的 `available_time`，`meta.as_of_event_time` 才是来源事件时刻；
两者不得互换。盘口 header 常驻显示价差 tick（`spread Nt`）；覆盖范围、微价格和完整价差细节通过中线悬浮说明提供。当前显示不做档位聚合，不扩大原始覆盖。

MON 的健康语义来自
`/api/v2/markets/{market_id}/book/l2/quality` 的 `l2-quality-v1` 五分钟窗口，
至少显示 fresh/stale、gap、sequence/regression、reject、深度范围和物化延迟。
bitbank market status 与三所 REST anchor 目前没有稳定 UI 合同，不能被前端暗并成
一个“健康”布尔值。未来展示 anchor 时必须同时给出 endpoint revision、触发原因、
可比深度和 `match/mismatch/unknown/unavailable`；GMO 与 bitFlyer 的近邻比较只可
显示 approximate/unknown。

## 3. 三段结构

盘口主体改为「卖方深度｜价格轨｜买方深度」三段式，同一价格行只在所属一侧绘制深度。卖方位于价格轨左侧并向左延展，买方位于右侧并向右延展；买卖两侧使用同一数量或金额基准与同一刻度。

默认档位行与中缝使用专用 `--h-ob-row` 高度，等档按钮启用后统一降为 `--h-row`；相邻报价之间按实际 bp 插入空档，空档高度再按 0.5 倍缩放，以便在有限纵向空间内同时保留价格距离和档位可读性。空档在价格列两侧画贯穿高度的点划测距导轨；高度至少一个紧凑单位时，直接标注实际缺失的 bp，便于同时目测比例和读取精确距离。工具行的等档为 chip 按钮，不是复选框；盘口不再自动回中，始终使用普通滚动浏览。

```text
卖方累计深度 ←  | 距中间价 / 价格 |  → 买方累计深度
██████           | +3 tick          |
███              | +1 tick          |
──────────────── 最优买卖报价条 ────────────────
                 | -1 tick          | ████
                 | -3 tick          | ███████
```

价格轨按距中间价的 tick 组织，最优档紧贴最优买卖报价条，远价档向外扩展。形状宽度表达带内**累计深度**，使外形具有单调、可比较的流动性含义；其上叠一条 2px 的**单档量细条**，用双侧共同的单档峰值缩放，以便从单调累计形状中重新识别局部墙量。累计与单档量不得共用不透明度或伪装为同一指标。刻度取双侧共同的滚动 95 分位或明确的固定上限，并在图中标注；超出刻度以截断标识，不悄然重标。

中条是最优买卖报价条，不是不可成交的中间价行：

```text
最优卖价 | 价差：1 tick · 1 JPY · <0.01 bp | 最优买价
```

中条为单行「带内卖深度｜中间价｜带内买深度」，与普通档行共用三列模板。卖侧数值向价格轨右对齐，买侧数值向价格轨左对齐，两个标签分别位于外侧；中间价单独居中，不再把 `t` 拼在中间价旁。价差 tick 在面板 header 显示，报价货币价差、bp、微价格和覆盖范围放入中线悬浮说明。盘口不平衡位于最右全高固定轨，上 ASK、下 BID，百分比直接居中叠在各自柱段。

MON 的单行实现把不平衡放在左侧深度列：百分比文字与条形分列，条形采用中央 0 线、左卖右买的发散结构，并在当前值端点绘制高对比端帽。文字不得压在动态填充上，避免更新时数字与颜色互相遮挡。价格与数量保持完整精度；空间不足时先横向压缩等宽数字，并提供完整值悬浮说明，不使用省略号，也不裁去数量级或小数有效位。

## 4. 指标定义

金额类计算在服务端以 `Decimal` 完成；响应同时给出数量与金额，前端的基准开关只选择显示字段。全部带内指标以最优报价两侧的实际档位过滤，不以「前 N 档」冒充 bp 带。

| 指标 | 定义 | MON 形制 | 条件与说明 |
|---|---|---|---|
| 最优买卖报价 | `best_ask`、`best_bid` | 中条首层 | 仅显示一个紧凑主价差；完整 tick、报价货币价差与 bp 通过悬浮说明提供 |
| 带内深度 | `D_side(w)=Σ size_i`，其中该侧档位距中间价不超过 `w` bp | 两侧累计深度形状与 header 摘要 | 缺省 5/10/25bp；数量与金额双口径 |
| 盘口不平衡 | `I(w)=(D_bid(w)-D_ask(w))/(D_bid(w)+D_ask(w))` | 中条末层 | 带宽由切换器和摘要明示，输出百分数 |
| 微价格偏离 | `micro=(ask×bid_size + bid×ask_size)/(bid_size+ask_size)`；显示 `micro-mid` 的 ticks | 中条次值 | 仅最优档存量派生，不能作为交易信号宣称 |
| 固定金额冲击 | 模拟以指定计价金额穿透同侧档位，输出 VWAP 与相对最优报价的 ticks | header 摘要或悬浮 | 金额、方向和覆盖不足须显式显示；默认不开启，参数由设置页提供 |
| 窗口成交流 | 窗口内主动买金额减主动卖金额、笔数与成交速率 | 独立窄带 | 仅第二阶段；不与盘口存量共用一个条形或刻度 |

阻力墙、存续期、净撤减等属于录制快照的时间特征，不进入第一阶段 MON。第二阶段如展示持续性，必须标注「快照近似」及观察窗口。

## 5. 动画契约

第一阶段不播放周期性充能、衰减或整行闪烁。REST 轮询只更新数值与一次性低对比变更底色；数据未变时不产生动画。

第二阶段的动画规则如下：

1. 查询服务将 WS 帧按 250ms 批次输出，保留来源事件或接收时刻与缺口状态。
2. 只有实际档级差异触发一次 120ms 至 560ms 的变更强调；新增、增加、减少、消失只描述快照差异，不命名为撤单。
3. 成交流使用独立的 1s 或 5s 固定窗口、共同且可见的刻度；不按近期局部峰值自动归一为满格。
4. `prefers-reduced-motion` 关闭全部变更动画，静态数值与色彩仍完整保留。

### 5.1 当前刷新与物化边界

GMO 官方限频表只明确公开 WebSocket 的 subscribe/unsubscribe 命令为每 IP 每秒 1 次；它不是盘口帧率。官方未公布 Public REST GET 的明确上限，私有 GET 的每秒 20 次不得套用到公开盘口。当前项目公开客户端总限速为 3 req/s，且同一服务还承载 ticker、status/clock 与 symbols 请求，因此 MON 盘口采用 500ms（2Hz）为当前数据链的最高可持续刷新档，而不是宣称交易所允许的绝对上限。

`/api/v2/markets/{market_id}/book/l2/latest` 按 `market_id + head_generation`
缓存状态；查询先验证并读取活动 `book_state_checkpoint`，缺失或陈旧才重放最近
snapshot 与 delta。checkpoint 是性能层，ETag 仍由 L2 head 决定。浏览器以五秒
ETag 条件轮询，同一 head 不重复读取或重放盘口。
数据只有在实时 segment 封口、物化并原子推进 head 后才变化，因此五秒是 UI
重验证频率，不是数据帧率或物化 SLA。后续接入增量 tile/推送后，再按事件推送
并在前端 250ms 合帧。

## 6. 接口与实现顺序

MON 当前读取 `/api/v2/markets/{market_id}/book/l2/latest`。服务端从最近完整
snapshot 重放后续 set/delete，返回最优买卖、价差、微价格、覆盖距离、
5/10/25/50bp 双口径深度及不平衡，同时保留 asks/bids 视图字段。旧
`/api/orderbooks` 仅为 GMO REST 兼容端点，不再是 MON 主数据。

质量徽章读取 `/api/v2/markets/{market_id}/book/l2/quality`，但盘口数值仍只来自
活动 L2 head。quality、market status 或 REST anchor 都不能改写 asks/bids；任何
旁路 unavailable 只降低健康呈现，不触发前端拼接 REST 全簿。

前端先将 MON 盘口替换为三段式静态深度剖面：统一刻度、最优买卖报价条、带宽切换与悬浮原始值。移除无尺度的边缘成交强度计与轮询驱动闪烁。第二阶段另建 WS 转发及批次差异接口，不以 CSS 动画伪造实时性。

验收条件：

1. 任一价位行的价格轨与最优买卖报价条精确对齐，最优档邻近中条。
2. 相同数量或金额在两侧拥有相同像素宽度；更换基准后形状和摘要同步变化。
3. 1 tick 的价差不会显示为 `0.00bp` 而失去信息。
4. 所有带内数值都携带 bp 带宽、基准和快照新鲜度；覆盖不足明确标注。
5. 在仅有 REST 数据时没有循环动画，且不出现撤单、队列或 L2 的不实表述。
