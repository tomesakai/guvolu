# 控制面与可视化设计

- **文档类别**：长期维护
- **地位**：X 章（SKILLS.md 第 5 章）的实现设计；TBD-12 至 TBD-17 的提案载体，确认后逐项标注【已锁定】
- **范围**：进程与通信架构、技术栈取舍、页面信息架构、UX 规范落地、分期实施

## 1. 设计前提（由既有规则推导，不再复述规则原文）

1. UI 是控制面不是数据源，关闭 UI 交易照常（X-01）——因此 UI 必须与执行进程**分进程**，两者只通过查询接口与事件流耦合。
2. UI 永不持有密钥——所有交易能力经执行进程代理，紧急停止不经策略进程（X-03、T-07）。
3. 陈旧即标注、无效不显示为零（X-06 与采纳评估的视觉正确性规则）。
4. 三面分离：监控、操作、研究不同屏（X-09），研究面阶段 9 后建设。

## 2. 进程与通信架构（TBD-13 提案）

```text
执行进程 ──追加写──> 状态存储（TBD-01 确定后落地）
    │                     │
    │ 事件推送             │ 只读查询
    ▼                     ▼
本地事件流 <────── 查询服务（read model，独立进程）
                          │ HTTP JSON + WebSocket 推送
                          ▼
                     浏览器 UI（零密钥）

紧急停止：UI 按钮 ──> 运维小进程（仅持撤单能力）──> cancelBulkOrder
                     （或人工直接运行 python -m guvolu.ops.kill_switch）
```

- **查询服务**独立于执行进程：读状态存储，向 UI 提供 HTTP JSON 查询与 WebSocket 事件推送。执行进程崩溃时查询服务仍能展示最后状态并明确标注陈旧。
- **操作命令**（模式切换、限额下调、策略启停）经查询服务转发执行进程，全部二次确认并留痕（R-07）；实盘切换仍需人工确认（A-01），UI 仅发起请求。
- **紧急停止**走独立运维进程，与 kill_switch 脚本同一实现内核，UI 不可用时脚本路径始终存在（T-07）。
- **认证（TBD-14 提案）**：查询服务仅绑定 127.0.0.1；启动时生成随机令牌写入本地文件，UI 首次访问读取；不做多用户体系。远程访问需求出现时另行评估，不预建。

## 3. 技术栈取舍（TBD-12 提案）

| 方案 | 优势 | 劣势 | 判定 |
|---|---|---|---|
| A：React + TypeScript + Vite，图表仅 ECharts | 单一图库覆盖 K 线、表格、热力图、血缘图；生态成熟；研究面（阶段 9）可复用同栈 | K 线交互不如专业金融图库；初始工程量中等 | 已被现行双引擎分工取代 |
| B：终端界面（Textual） | 最快可用；无浏览器依赖；适合纯监控 | 图表能力弱；回放游标、血缘下钻、研究面无法承载；后期必然重写 | 仅作过渡可选 |
| C：React + 专业金融图库（如 K 线专用库）+ ECharts 双库 | 价格图体验最佳 | 双库双学习成本，违背单一图库先行原则；许可标注负担 | 暂缓，A 被证明不足时再升级 |
| D：桌面框架（Electron/Tauri） | 原生体验 | 打包与更新负担，收益与本地 Web 无异 | 拒绝 |

现行选择为 React + TypeScript + Vite；Lightweight Charts 承担时间轴价格与
stacked-area 系列，OFL 使用面向稀疏 tile 的自定义画布。ECharts 只在后续统计分析
图确有收益时引入，不作为当前依赖前提。视觉正确性、单位、缺口与降采样规则由
本文件统一，不依赖具体图库。

后端查询服务用 FastAPI（Python 同栈，与执行进程共享 domain 模型，序列化零重复定义）。依赖锁定版本（C-05）。

**陈旧度标注**（X-06 落地规范，形制按 [design-language.md](design-language.md) 第 4、6 节）：每个实时面板携带 `last_updated` 新鲜度徽章；**旧数据保持可见**，断流时徽章转警示并显示相对陈旧时长，面板顶部细横幅给错误码；绝不静默显示旧值为当前值。无效值一律渲染为「—」。

**多来源资产视图**（2026-08-11 增设）：资产面板工具位提供「总览 / GMO Coin / bitFlyer」选择。总览按币种并行列出各所的 amount 与 available，再列同币种合计；它不是跨币种净值，也不做汇率换算。某所未配置、读取失败或未返回某币种时保留该所列并显示「—」，来源状态在面板元数据明确标示，禁止以零值替代。amount 与 available 均为交易所原始字段，抵押、未实现盈亏、可取现额等其他私有端点字段不并入资产表；如需展示，必须以独立模块和原始字段名进入操作面。amount 与 available 均为零的行缺省折叠，折叠控件只改变显示。

**MON 纵向盘口编排**（2026-08-11 增设）：盘口与右侧「挂单+成交」组合槽互换，但两个外框槽的长宽保持不变。盘口使用原账户活动槽的纵向空间表达离中间价的价格距离；挂单与成交使用原盘口槽，并在内部横向等分，作为同一账户活动域并列扫读。响应式布局只搬移槽位，不改变该信息邻接关系。

**MON header 审计**（2026-08-11 增设）：命令条已经给出全局品种，子面板不再重复。K 线周期、查询范围预设、盘口 bp 带与热力时间窗已经由选中控件表达，不再复制到右侧元数据。来源和新鲜度属于状态事实，始终保留；挂单/成交计数、热力价区、OFL 缺口属于本面板独有信息，允许保留。根数、行列数、阶段号与设置存储键只适合诊断，不进入默认 header。

**MON 浮动停靠与盘口扩展**（2026-08-12 修订）：资产、挂单、成交、热力以单一浮动停靠栏管理，常态为贴工作区左下角的四个图标，不占任何网格行；展开层同样贴左、下边缘并与盘口共用分界线。盘口从工作区顶端到底端全高展示，K 线占左侧最新价以下余高；最右侧使用贯穿面板高度的固定 ASK/BID 上下伸缩轨，颜色表达方向、柱高表达该侧带内占比，ASK/BID 百分比分别贴近中央分界线并保持上下对齐；中缝与档行等高且单行，价格列完全复用各档价格列，ASK 数据右对齐、BID 数据左对齐，只放中间价与双侧绝对深度，价差 tick 移至盘口 header，微价格、报价货币价差和覆盖范围放入悬浮说明。工具行的「等档」为 chip 按钮：未激活时维持逐档等高扫读，激活后按真实 bp 间距留下比例空白，同时降低档位/中缝行高并缩小空档共同尺度；价格列两侧以点划导轨贯穿每段空档，空档足够高时显示实际缺失 bp，精确说明间隔大小。盘口不再自动回中，使用普通滚动浏览。资产展开时仍复用单行表头，且不改变最新价轨道。

### 4.1.1 K 线尺度、按钮与投射审计（2026-08-11）

K 线工具行同时包含五种不同层级，必须按下面的顺序理解，不能把查询范围与图内缩放当成同一件事：

| 层级 | 当前入口 | 正确语义 | 裁定 |
|---|---|---|---|
| 数据粒度 | `1min` 至 `1month` 下拉 | 服务端 K 线聚合周期；改变每根 bar 的时间宽度 | 常驻，排第一 |
| 查询范围 | `7日/14日/24日` | 改变请求覆盖，不等于把图缩放到若干日 | 常驻，排第二 |
| 图内时间视窗 | 滚轮、拖动 | 只改变当前可见 logical range，不重新请求 | 直接手势优先；离开最新端后才出现“最新/适配”恢复入口 |
| 价格尺度 | `线性/对数` | 改变同一价格数据的纵轴映射 | 线性缺省；对数用于长范围和大相对波动，不与图型混组 |
| 派生投射 | `区间高低/盘口` | 在主图上叠加查询区间高低线或当前盘口轴刻线 | 可独立开关；名称必须说明对象，不用“极值/轴投影”泛称 |

当前视窗保存与恢复已实施：同一 `symbol|interval|range` 数据键刷新时保留 logical range，图型切换以时间范围恢复；只有换查询键或首次装填才 `fitContent`。用户原本位于最新端时随新数据推进；拖离后停止自动跟随并显示「最新」，点击后回到右端但保留当前尺度。「适配」常驻，适配当前查询全范围并恢复各窗格价格自动尺度；两者均不在普通刷新时强制回中。

尺度效率按图型分派：蜡烛、美国线与足迹需要可辨认的单 bar 宽度，不应长期允许多根压入一个像素；线、面积与基线可以更密，并可使用库的连续序列 conflation。当前统一 `minBarSpacing=0.05` 对蜡烛过密，后续应按图型设置下限并在大于一万点的连续序列上评估后台预计算，不能对蜡烛做会改变形状含义的激进合并。

盘口投射只把**当前快照**的价格和单档数量分位投到右价格轴，不是历史热力，也不随时间轴形成轨迹；保持短刻线而不画满宽深度带。区间高低取当前查询覆盖的最高/最低，不命名为交易会话高低。所有投射必须随可见价格尺度、线性/对数切换和面板尺寸同步重绘，关闭后清空画布，不保留陈旧墨迹。

### 4.4 功能分页与全组件互动契约（2026-08-09 定稿）

分页判据是**工作形态**而非数据域——同一数据可现身多页，每页只承载一种工作节奏：

| 页 | 工作形态 | 独有交互 |
|---|---|---|
| MON | 扫读（满幅无滚一瞥全局） | 品种周期图型切换；热力速览仅悬浮与桶 chip |
| OFL | 工作会话（深潜单一疑问） | 点击追踪、框选分析、报警确认、导航条拖框——全应用唯一的框选与抽屉 |
| CAP | 盘点（能力与覆盖） | 采集拉起与停止的汇总面 |
| SET | 配置（显示层偏好，含价格图型） | 即时生效控件 |
| KILL | 应急 | 命令说明展开 |
| OPS / RPL / RSC | 预留（6b / 8 / 9） | RPL 将持有全局回放游标；RSC 与执行永不同屏（X-09） |

CAP 应升级为统一数据健康页，但只消费控制面低基数摘要与活动 head：按
venue/market/domain 展示 raw open、sealed、materialized、quality、market status、
REST anchor、覆盖和任务状态。高基数 `artifact_id`、attempt、connection、frame 或
payload SHA 只在下钻日志/血缘中按需查询，不作常驻时序标签，以免基数和渲染成本
随数据量增长。核心时序指标仅保留 fresh/stale、sealed-to-materialized lag 与
gap/reject/reconnect 等少量维度。

REST anchor 的状态必须区分 `match`、`mismatch`、`unknown`、`unavailable`，并显示
端点修订、触发原因和可比深度。GMO/bitFlyer 的 approximate 比较不得涂成红色
full-book mismatch。当前 market status 和 anchor 尚无稳定公开 UI/API，故 CAP
只预留位置，不直接读取 SQLite 或原始文件。

跨所顶档视图只消费 `GET /api/v2/aggregates/book/top`：同时显示实际 contributors、
quorum、decision time、每所新鲜度、synthetic bid/ask、mid median 与 `crossed`。
crossed 不裁平、不以单所颜色掩盖；响应 `no-store`，无显式 FX 时不允许把 JPY 与
USD/USDT 市场放入同一聚合控件。

分页四纪律：深交互升页速览留 MON（交互密度越过一瞥阈值即升页）；跨页入口 chip 允许但状态不跨页泄漏；控制出现在需要它的地方（空态与陈旧态就地拉起，CAP 只做汇总）；报警为唯一全局横切件（全局 header 报警槽全页可见，**点击跳转 OFL 报警页签**——2026-08-09 确认，2026-08-10 迁移位置）。

**品种上下文全局唯一**（2026-08-09 确认）：命令条持有，全页跟随；多源落地后升格 `来源 · 品种` 形制；同图多源对照留给参考价阶段。

**动词契约**（六动词全应用同义）：悬浮=只读 kv 揭示，永不改状态；点击 chip=模式开关，永不是危险动作；点击数据元素=唤出上下文工作件（档带→追踪抽屉，事件与报警→视窗跳转加轮廓高亮）；滚轮拖拽=视窗操纵（梯形滚轮即转手动模式）；框选=仅 OFL 主图的区域分析；确认按钮=唯一交互写动作（报警确认，零交易语义）。

**分层同步**：窗格级原生联动 → OFL 同 canvas 共享 x 变换（导航条为该层唯一主控）→ 同刻度组镜像（阶段 5 账户图组预留）→ 回放游标为将来唯一全局时点同步（阶段 8）。十字线永远本地。

**状态持久化分级**：显示偏好 localStorage；报警确认服务端 alert_event；视窗、抽屉、模式为会话内存（刷新回缺省——工作会话不留残局）。

**尺度模型（2026-08-09 定稿）**：两条尺度链贯穿全应用，一切缩放与下钻交互沿链移动、不跳链不自创档。

- **时间链**（小→大）：逐笔 → OFL 桶（100ms 灰 · 1s · 5s · 1min）→ K 线周期（5min 至 1month）→ 会话（JST06 交易日）→ 覆盖全程（导航条与「全部」预设）。每档的可用性由来源节奏决定（诚实降级），显示分辨率永不细于数据分辨率。
- **单位链**（小→大）：tick（品种规则最小变动）→ 足迹档宽（tick×档位）→ bp 带（5/10/25，相对中间价）→ 基准（数量 BTC ↔ 金额 JPY，全局 SET）→ 呈现变换（精度归一 → 千分位 → k/M 缩写，语义类各就各位）。上游是数据事实，下游是显示变换，方向不可逆流（显示层永不回写语义）。
- **跨尺度下钻契约**：下钻=沿时间链向小、携带上下文（品种、时间窗、价位带）——K 线 bar（足迹型）可跳 OFL 对应时间窗；OFL 档带点击入追踪（单价位纵剖）；框选入区域分析（时价矩形）；事件与报警点击反向定位（视窗跳转加轮廓）。上卷=沿链向大，只收缩细节不丢上下文。任何新组件先声明其在两链上的位置，再定交互。

## 5. 回放游标（采纳评估既定方向，阶段 8 实现）

所有视图共享单一游标 `{run_id, cursor_time}`：价格图、挂单表、成交表、持仓与限额面板按同一时刻渲染。任一视图点击事件即跳转全局游标。数据基础是 R-07 全量留痕加 D-01 血缘——correlation_id 与 orderId 使「从一笔成交回溯到该时刻全部状态」成为查询而非推断（X-08）。MVP 不实现，但查询服务的接口从一开始就带 `as_of` 参数预留。

## 6. 视觉正确性规范（全部图表通用）

1. 每张图标注：时区（显示层 JST，数据 UTC）、单位、gross/net 属性、数据定义版本。
2. 降采样必须保留极值与成交事件点，禁止纯均值抹平。
3. 同一色标必有图例与归一化模式标注；缺口用不可混淆的纹理，不用背景色填充。
4. 悬停显示原始值与聚合范围。
5. 导出截图附带查询参数与时刻。

## 7. 告警（TBD-16 提案）

阶段 6 仅两级：界面横幅（熔断、断流、对账不一致）加日志留痕。推送通道（邮件或即时消息）在实盘资金上量前再评估，不预建。

过渡形态（6-pre 查看版）：状态存储落地前，查询服务实时转发 READ_ONLY 与公开端点取数，仍守零密钥进浏览器与仅本机绑定两条约束；执行进程出现后改读状态存储，前端不变。
