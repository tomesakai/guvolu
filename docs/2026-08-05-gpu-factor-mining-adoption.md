# GPU 因子挖掘资料采纳评估（2026-08-05）

- **文档类别**：时效快照（内容冻结，修订以新快照发布）
- **评估对象**：仓库内 `gpu-factor-mining-v1.1/`（32 个文件：规范文档 17 份、ADR 5 份、Protobuf 契约 6 份、清单与索引）
- **评估目的**：抽出可用于本项目的架构语义与标识体系，界定采纳、改制、搁置与拒绝的范围

## 1. 资料概貌与客观评价

该资料集是一套「GPU 加速因子挖掘系统」的工程规格（v1.1-draft），假设 Rust 模块化单体、CUDA（RTX 5070）、React 前端与多团队组织，覆盖：领域语义、数据平台、表达式编译、GPU 运行时、分级评估、统计治理、组合执行、进化搜索、注册表与可视化十个领域。

值得肯定的特征：

- 证据分级制度贯穿全部文档（实证来源、算术推导、决策、阈值、待基准、待研究六类标记），未实测的性能数字一律撤销或标记待测；
- 语义定义（时间、身份、指标、订单状态）与实现技术解耦，可移植性高；
- 反过度拆分立场明确：模块边界靠领域所有权与契约，独立进程仅限资源故障隔离、安全权限隔离、生命周期差异三类理由。

客观限制：

- 纯设计文档，无实现与实测，其自身标记也承认关键吞吐与阈值未定；
- 组织与技术规模假设（多团队、Rust/Protobuf/gRPC、四套前端图库、Grafana 全套）远超本项目；
- 市场假设为 Binance 类交易所与 ETF，与 GMO Coin 实际约束存在硬性差距（见第 6 节）。

## 3. 标识体系采纳方案

现行 D-05 已要求标识全局唯一且稳定。采纳内容寻址后，标识统一为两类。

内容散列标识（确定性产物，SHA-256，输入相同则标识相同）：

| 标识 | 输入 | 用途 |
|---|---|---|
| expression_id | 规范化因子表达式 | 表达式身份与去重 |
| candidate_id | expression_id 加参数 | 候选身份与缓存复用 |
| evaluation_id | candidate_id 加面板、标签、成本、代码版本 | 评估唯一性与确定性重放 |
| config_hash | 规范化配置 | D-09 既有 |
| 制品散列 | 文件内容 | 大文件身份，存放路径可变而散列不变 |

事件标识（非确定性，生成后不变）：

| 标识 | 生成方式 | 用途 |
|---|---|---|
| client_order_id | 自生成唯一，格式受 GMO 字段约束，具体上限待实测（A-04） | T-05 既有 |
| run_id | 每次进程会话生成 | D-05 既有 |
| correlation_id | 每条因果链生成一次，贯穿研究、执行、账本、日志 | 新增，全链路追溯 |

配套规则一并采纳：散列命中后仍比较规范化原文（防碰撞）；规范化仅做语义保持变换，浮点代数重排默认禁止；schema_version 沿用 D-06；控制信息传制品散列引用，不内嵌大数组。

## 4. 该聚合的聚合

资料的十个一级领域在本项目聚合为既有目录结构，不新增顶层模块：

| 资料模块 | guvolu 归属 |
|---|---|
| Domain Semantics、Data Platform | src/guvolu/domain 与 data |
| Expression Compiler、CPU Reference、GPU Runtime、Evaluation | src/guvolu/research（CUDA 后置，CPU 先行） |
| Statistics Governance、Ledger & Registry | src/guvolu/research 内的台账与治理组件 |
| Portfolio & Execution | 既有 api、strategy、risk |
| Search & Evolution | src/guvolu/research（阶段 9 后） |
| Visualization & Observability | src/guvolu/ui |

进程保持四个：执行、研究、UI 查询、紧急停止开关。CUDA 到位后 GPU 计算独立为研究侧子进程，理由与资料一致——Windows WDDM 的 TDR 约两秒超时与驱动崩溃需要进程级隔离，本项目同为 Windows 平台，该约束直接适用。

Protobuf/gRPC 不引入：进程内用类型化 Python，进程间沿用文件与数据库约定。保留其四点思想——版本化 schema、写命令幂等键、correlation_id 贯穿、大数组传引用不传值。

## 5. SKILLS.md 修订提案（待确认，不自行变更）

| 提案 | 内容 | 理由 |
|---|---|---|
| P-1 | D-03 三时间扩为四元组：新增 available_time（最早可合法得知时刻）与 revision_id（修订链）；D-04 的 PIT 判定由 ingest_time 改为 available_time | 回补历史数据时 ingest_time 是下载时刻，失去 PIT 意义；修订链支撑 D-02 之下游修正的表达 |
| P-2 | 新增规则：一切筛选阈值、预算、配比为版本化配置，随评估记录留存，不得写成事实或普适结论 | 防止项目阈值伪装成统计结论，与 A-04 同源 |
| P-3 | G 章新增两条：研究试验台账追加式全量登记（含被拒候选，供多重检验校正使用）；封存段一次消费，检验失败后的新版本不得复用同段声称样本外 | 多重试验校正要求完整试验计数；样本外结论的可信性依赖一次消费纪律 |

## 6. GMO 约束下的客观差距

| 资料假设 | GMO 实测事实 | 影响 |
|---|---|---|
| 横截面 512 标的 | 现物 17 品种、杠杆 12 品种（2026-08-05 实测 /v1/symbols） | 横截面秩类因子统计功效不足，研究重心应为时序类与小截面因子；截面最小样本数门槛按实际品种数重设 |
| 增量 L2 订单簿与序列号 | 仅盘口快照与逐笔成交 | 模拟上限为「快照盘口加逐笔成交」的近似 B2，禁止声称 L2 回放 |
| 撤改单密集的执行算法（VWAP、POV 等） | 20 req/s 限速，R-04 自我约束 10 req/s | 首版执行算法止于即时窗口与时间切片两档 |
| 多市场日历与竞价窗口 | 加密 24 小时连续，交易日界 JST 06:00（D-08 既有） | 决策时钟简化为固定 UTC 时点，无竞价窗口建模 |
| 资金费率、借券、公司行动会计 | 现物无此三类 | 会计事件集缩减为成交、手续费、划转三类 |
